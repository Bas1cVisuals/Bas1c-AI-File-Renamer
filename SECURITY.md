Reporting a Vulnerability
If you discover a potential security vulnerability, please report it responsibly.
Please do not publicly disclose security vulnerabilities through GitHub Issues or Discussions.
Instead, use GitHub's private vulnerability reporting feature, if enabled for this repository.
When reporting a vulnerability, include:

A clear description of the issue.
Steps to reproduce the vulnerability.
The affected version or component.
Potential security impact.
Relevant screenshots or logs, if available.

Please avoid including personal images, sensitive information, credentials, or private files in your report.
Security Considerations
BAS1C AI Image Renamer is designed to process files locally. However, users should keep the following considerations in mind:

Local processing: Image analysis is performed through the locally installed Ollama service and configured vision model.
Model security: Ollama models are third-party components. Only install models from trusted sources.
File permissions: Run the application with standard user permissions. Administrator privileges should not normally be required.
File renaming: Review proposed filenames before applying changes. Always maintain a backup of important files.
File access: Only select folders and files you are authorized to access.
Dependencies: Keep Python, Ollama, and project dependencies updated.
Untrusted files: Avoid processing suspicious or potentially malicious files.
Reports and logs: Rename reports may contain local file paths. Do not publish them publicly if they reveal private information.

Privacy
The application is intended for local use. Image files are processed using the configured local Ollama service.
This does not constitute a guarantee that every component operates offline. Users should independently verify their Ollama configuration, installed models, dependencies, and network activity.
Scope
This policy covers security issues directly related to the BAS1C AI Image Renamer source code and its documented functionality.
Issues involving third-party software, operating systems, Python packages, or Ollama should also be reported to their respective maintainers when appropriate.
